## 做了什么

- 增加部署参数 `APP_NODE_ID=1001..1008`，节点 ID 固定映射 470.3–471.7 MHz，取消板型固定频率。
- 节点改为 5 秒周期：4.00 秒正常上传、250 ms 控制、200 ms 并行确认、550 ms 补传。
- 上位机默认 8 节点，增加 E870 TX 范围前置检查、全部节点确认、未知节点隔离和每节点批量 ACK。
- 重复 START 在当前运行结束前会被拒绝，STOP 可重复执行；全部目标节点回到待机后才清理当前运行，避免运行编号和迟到数据污染。
- GUI 预先显示全部目标节点（包括离线节点），增加信道、在线、确认、GNSS/PPS、采样时钟、队列、包数、样本数、RSSI、SNR、丢包/丢样和补传状态。
- 默认 50 Hz/SF6；100 Hz 必须显式选择并使用 SF5，不允许从 50 Hz 自动切换。
- 质量报告增加每节点和整体到达率、补传率、最终缺失率、最大延迟和 10 秒内到达比例。
- 长期文档更新为 E870 八节点方案；`docs/changes/` 只保留本报告。

## 接线、烧录和操作变化

- 接线不变；8 个节点可使用任意现有板卡/传感器组合。
- 烧录前设置唯一 `APP_NODE_ID`，烧录后核对 BOOT 的节点和上行频率。
- 上位机启动时通过 `--gateway-config` 验证原配置的 470.3 MHz TX 范围；未验证时只允许接收。
- 实机按 1、2、4、8 节点分级扩容，先完成 50 Hz，再进入 100 Hz/SF5。

## 验证结果

- 完整 Python 测试：137 项通过，1 项因缺少历史采集数据文件而跳过。
- 四种正式环境构建通过：Heltec V3.2 / EoRa-S3-400TB 分别搭配 IIM-42352、IIM-42652。
- 代表环境以 `APP_NODE_ID=1001..1008` 分别完成覆盖构建，8 个节点配置均通过。
- 非法 `APP_NODE_ID=1009` 在构建前明确报错并拒绝继续。
- E870 射频、烧录、8 节点确认和 2 小时采集：未连接硬件，待实测。
