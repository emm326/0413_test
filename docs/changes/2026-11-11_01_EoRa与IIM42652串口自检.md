# EoRa 与 IIM42652 串口自检

- 日期：2026-11-11（Asia/Hong_Kong）。
- 对应步骤：硬件验收第 1 节“单节点硬件”，为实施计划步骤 3–6 的实机联调前置检查；当前进行中，无线和多节点阶段继续为待实测。
- Git 基线：`393bd3e`（`codex/e870-8-node`），检查前工作区无改动；历史清理前代码仍可通过 `archive/pre-cleanup-20261108` 查询。

## 做了什么

1. 阅读根目录计划，沿用 EoRa-S3-400TB + IIM-42652、原接线、协议 v3 和 32000 Hz 时钟配置。
2. 检查 Windows 当前设备和 PlatformIO 串口列表，识别到 COM8，硬件 ID 为 `USB VID:PID=303A:1001`，设备序列号为 `90:DA:72:76:1F:30`。
3. 以 460800 波特率打开串口，两次观察分别读到 3 条状态日志，共 6 条，内容一致。
4. 对照当前固件的状态枚举和启动逻辑，确认 `state=5` 表示 Fault；此状态由时钟输出、传感器和无线初始化的检查结果决定，不能单凭 `gps=0` 解释启动故障。
5. 尝试 USB 控制线复位以捕获启动日志；未收到 BOOT/READY，不能确认该次复位成功或具体初始化失败项。检查期间串口曾断开，后续枚举曾重新出现，最后一次尝试时设备不在串口列表。检查结束已释放串口。
6. 按项目规则移除已进入 Git 历史的旧变更报告，更新实施计划、长期验收记录和本轮报告。

```text
STATUS,id=1003,state=5,gps=0,clock_hz=0.0000,ppm=0.00,clock_ok=0,queue=0,lost_samples=0,lost_packets=0
```

| 检查 | 结果 | 解释 |
|---|---|---|
| USB/串口通信 | 已读取到日志 | COM8 可以打开，收到周期性状态；检查期间曾断开，稳定性尚未确认 |
| 节点编号 | 1003 | 来自实际状态日志；板型、传感器型号和固件版本的 BOOT 字段尚未独立核验 |
| 启动自检 | 未通过 | state=5；具体失败项需要 READY 中 sensor、radio、clock_output 字段定位 |
| GNSS/PPS | 未就绪 | gps=0，尚未核实原因是未接线、未定位还是输入未满足固件健康条件 |
| 时钟测量 | 未就绪 | clock_hz=0.0000、clock_ok=0；ppm=0.00 不是通过证据，也不能据此断言时钟输出为零 |
| 采样与无线链路 | 待实测 | 尚未启动采集、未测试 E870；零丢失计数不能证明实际采样或传输正常 |
