## 做了什么

1. 新建独立PlatformIO工程`minimal_six_wire_iim42652/`，不引用主工程的LoRa、GNSS、CLK、NodeApp或传感器业务代码。
2. 程序只操作六个信号：VCC、GND、SCK47、MOSI48、MISO39、CSB40。INT1、INT2/CLKIN和GNSS均不初始化。
3. 启动和收到`SCAN`时执行：
   - 分别将CS、SCK、MOSI拉低和拉高并读回引脚电平；
   - 将MISO先上拉、再下拉，判断是否存在浮空或持续低电平；
   - 以Mode0/100kHz、Mode0/1MHz、Mode3/100kHz、Mode3/1MHz各读取WHO_AM_I 8次。
4. 每次读取发送地址字节`0xF5`和一个dummy字节，只比较`0x6F`；程序不写任何传感器寄存器，不发送DEVICE_CONFIG软件复位。
5. 增加CSB改接GPIO35的备用构建环境，用于隔离GPIO40板级问题。

## 判断与限制

CS引脚由ESP32主动输出高电平时仍读回0，说明GPIO40或CSB线路被外部持续拉低。正常IIM42652的CS是输入且默认内部上拉，不应阻止GPIO输出高电平。最可能的物理原因是：

1. CSB误接GND；
2. CSB线、排针或模块焊点对地短路；
3. GPIO40板级输出异常或与其他低电平信号相接；
4. 模块板级电路将CS持续拉低。

MISO上拉仍读0可能由两个原因造成：CS持续为低时芯片正在驱动MISO低，或MISO线路本身对地短路。现有测试不能区分这两项，因此不能据此判定传感器损坏。

本轮只证明软件构建、烧录、串口通信和引脚测试有效。没有取得0x6F，没有验证DRDY、FIFO、CLKIN、GNSS/PPS或采样。

## 下一步

1. 完全断电，确认传感器VCC为3.3V、GND共地，并拆除INT1、INT2/CLKIN和其他非六线连接。
2. 只拆下CSB与GPIO40的连接后重新上电，执行`SCAN`。
3. 若`CS high_read=1`，说明GPIO40本身可输出高电平；检查CSB是否误接GND、线端短路或模块持续拉低。
4. 若拆线后`CS high_read=0`，判断GPIO40板级异常；断电后将CSB改接第23脚GPIO35，烧录`eora_s3_400_iim42652_six_wire_alt_cs`。
5. CS正常后重新检查MISO。只有六线扫描稳定返回0x6F，才接回INT1和CLKIN，再恢复正式固件和采样验收。
