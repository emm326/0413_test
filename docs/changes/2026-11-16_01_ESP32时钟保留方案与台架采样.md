# ESP32 时钟保留方案与台架采样

## 对应步骤

阶段 4～5 的实机恢复：保留 ESP32 GPIO36 作为 IIM42652 外部时钟，不使用 DS3231。

## 本轮 Git 基线

- 本轮基线：`8a4bb8c`（test: 保存IIM42652时钟与FIFO实机调试基线）。
- 分支：`codex/sensor-recovery-20261114`。

## 做了什么

1. 时钟输出改为可自检、可恢复的实现。
   - 启动时等待 10 ms 统计边沿，要求 240～400 个（32 kHz 理论值 320）。
   - 恢复路径重新执行 `ledc_channel_config`，不再使用会断开 ESP32-S3 输出矩阵的 `gpio_ll_output_disable`。
   - 停止时钟改为 `ledc_timer_pause`，引脚不再悬空。
   - 运行期每秒检查一次边沿数，连续两次异常触发一次重新挂接。
2. 修正 INT1 配置。
   - 清零 `INT_CONFIG1`（0x64）bit4 `INT_ASYNC_RESET` 并读回确认，手册要求该位为 0。
   - 读回 `INT_SOURCE0`，确认只开 FIFO 阈值中断、关闭 DRDY。
3. 修正 FIFO 计数含义。
   - 手册默认 `FIFO_COUNT_REC=0`，FIFO_COUNT 单位是字节；驱动按记录消费。
   - 改为 `FIFO_COUNT_REC=1` 并读回，读取计数时增加 3 次重试，避免启动瞬间 0xFFFF 被当成溢出。
   - 单条记录损坏只记一次间隔，连续 3 次才判故障。
4. 采样流程加固。
   - INT1 使用内部下拉；中断增加 2 ms 去抖。
   - 启动自检从 1 次改为最多 3 次。
   - 开始采集时重新挂接 INT1，并等待 100 ms 让首批 FIFO 记录产生。
5. 增加台架模式。
   - 新增编译开关 `APP_REQUIRE_TIME_SYNC`，台架环境设为 0。
   - 无 GNSS 时使用固定基准加运行时间作为时间戳，GPS 标志仍为 0，表示时间不可信。

## 验证结果

### 编译

- `eora_s3_400_iim42652_bench` 构建通过。
- `eora_s3_400_iim42652_tx` 正式环境构建通过。
- `tests.test_firmware_sensor` 3/3 通过。

### 实机

| 项目 | 结果 |
|---|---|
| 时钟自检 | 多次上电均为 `edges_10ms=320, ok=1` |
| 时钟稳定性 | `clock_delta=160000`（5 秒窗口，等于 32 kHz） |
| 传感器身份 | `WHO_AM_I=0x6F` |
| 启动自检 | `drdy=19, fifo_samples=12, clock_edges=3840, sample_valid=1, ok=1` |
| 采集启动 | `CONFIRM,result=0,state=2`，接受 30 秒采集 |
| 有效样本 | 25 条，Z 轴约 8280 LSB（±4 g 下约 1.0 g） |
| 时间戳 | 台架基准 1767225613xxx，单调递增 |

### 未通过项

1. 样本时间间隔不均匀。实测 `dt` 出现 0、18277、20000、80107、119907 微秒，50 Hz 应接近 20000。
   原因：INT1 边沿不足时，一个采集批次内多条 FIFO 记录共用同一主控时间戳；FIFO 内建时间戳尚未使用。
2. 采集约 5 秒后再次出现 `SENSOR_FAULT,invalid_fifo_bytes`，进入 state=5。
3. 因此连续 60 秒采样和 LoRa 传输本轮未通过验收。

### 结论

ESP32 时钟本身已稳定，传感器可以启动、输出正确 XYZ 数据。采样时序和长时间稳定性仍未达标，不能标记阶段 4～5 完成。
