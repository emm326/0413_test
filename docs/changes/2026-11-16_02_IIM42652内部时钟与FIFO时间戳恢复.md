## 对应步骤

## 问题与结论

结论：传感器已能启动并连续采样，单节点 60 秒验收通过。ESP32 GPIO36 的 32 kHz CLKIN 在本板上无法稳定输出，固件自动回退到 IIM42652 内部时钟；样本间隔使用传感器 FIFO 内建时间戳计算，不再依赖 INT1 边沿计时。

根因有三个：

1. GPIO36 的 MCPWM 32 kHz 输出在本板上数秒后失效。启动自检读到 `pcnt_50ms=0`、`poll_50ms=0`，5 次恢复仍为 0。
2. 旧采样代码用 INT1 中断时间作为样本时间，FIFO 轮询与中断边沿不是一一对应，导致样本间隔漂移。
3. FIFO 读取按单字节事务执行，长包读取时容易遇到总线时序与包头错位。连续失败还会立即进入 Fault，没有单次故障恢复。

## 做了什么

1. 时钟源自动回退。
   - 启动时先尝试 GPIO36 外部时钟，并要求 PCNT 与轮询两种方式都看到边沿。
   - 外部时钟不可用时关闭 CLKIN，重新用 `external_clock=0` 初始化传感器。
   - 启动自检在内部时钟模式下不再要求 DRDY 或 GPIO36 边沿。
2. FIFO 使用内建时间戳。
   - 配置 `TMST_CONFIG=0x29`：使能时间戳、16 µs 分辨率编码、DELTA 模式。
   - 每个 16 字节 FIFO 包包含加速度 6 字节、陀螺仪占位 6 字节、温度 1 字节、时间戳 2 字节。
   - 时间戳按 16 位循环计数计算差值。内部时钟模式下按说明书比例 `16×32/30 = 17.067 µs/tick` 换算，即 `58593 ticks/s`。
   - 时间差异常时回退到标称 20 ms，并计入 `ts_anomaly` 和 `fallback`。
3. FIFO 读取改为批量事务。
   - 一次 `transferBytes()` 连续读出整批 FIFO 数据，再在内存中逐包解析。
   - 每 5 ms 轮询一次 FIFO，避免高频轮询压垮 100 kHz SPI 总线。
   - 记录 `count_raw`、`header`、`packet_bytes`、连续失败次数、累计失败次数和恢复次数。
   - 单次 FIFO 故障执行一次受控恢复；连续 3 次才进入 Fault。
4. bank 切换与寄存器读回。
   - `setBank()` 写入后物理读回 `REG_BANK_SEL`，失败重试 3 次。
   - `WHO_AM_I` 读取失败时重试，避免单次零值被误判为传感器掉线。
5. 启动自检调整。
   - 外部时钟模式要求 3000～4700 个时钟边沿。
   - 内部时钟模式不要求时钟边沿。
   - FIFO 样本数要求 4～30，且样本和 `WHO_AM_I` 均有效。

## 验证结果

### 编译与离线测试

- `tests.test_firmware_sensor`：3/3 通过。
- `eora_s3_400_iim42652_bench`：构建通过，RAM 54652/327680 字节，Flash 389285/1310720 字节。
- `eora_s3_400_iim42652_tx`：构建通过，RAM 54668/327680 字节，Flash 391477/1310720 字节。
- 完整 unittest 回归：86 项中 20 项通过；其余 66 项在 Windows 临时目录清理阶段报 `PermissionError`，不是断言失败。该问题来自测试环境文件句柄未释放，与本轮固件改动无关。
