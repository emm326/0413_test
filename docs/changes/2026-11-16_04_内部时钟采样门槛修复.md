# 内部时钟采样门槛修复

## 对应步骤

阶段 4～5 的单节点 50 Hz 采样恢复。目标是让 IIM42652 在 GPIO36 外部 32 kHz 不可用时，使用自身内部时钟正常启动采样，同时继续要求室外 GNSS/PPS 健康。

## Git 基线

- 本轮基线：`cb099e7`（test: 完成室外GNSS与PPS六十秒复测）。
- 分支：`codex/sensor-recovery-20261114`。
- 本次代码、计划与本报告随本轮提交。

## 问题

正式采样门槛直接使用 `SampleClock::healthy()`。该状态只表示 GPIO36 外部 32 kHz 的频率测量结果。传感器回退到内部时钟后，GPIO36 本来就没有 32 kHz 输出，因此该测量永远失败，`clock_ok` 始终为 0。

这不是传感器采样故障。传感器启动自检已经证明内部时钟和 FIFO 能产生有效样本，问题在正式采样门槛把两种时钟模式混用了。

## 做了什么

1. 新增统一判定 `clockReadyForCapture()`。
   - 外部时钟模式：必须通过 GNSS/PPS 的 60 秒 32 kHz 测量。
   - 内部时钟模式：必须通过传感器启动自检；采样期间由 FIFO 计数、包头、时间戳和连续失败次数监控。
   - 传感器未启动时，两种模式都判定为未就绪。
2. 正式启动门槛、`STATUS`、数据包时钟标志统一使用新判定。
3. `STATUS` 增加 `clock_source=external|sensor_internal`，避免把 `clock_ok=1` 误解为外部时钟测量通过。
4. 内部时钟模式下，`READY` 输出 `clock_measurement=sensor_internal_fifo`。
5. 增加 4 个门槛策略断言，覆盖外部时钟、内部时钟和传感器未就绪三种情况。

### 启动门槛

```text
SENSOR_CHECK,init=1,executed=1,drdy=6,fifo_samples=16,
clock_edges=0,clock_source=sensor_internal,sample_valid=1,
identity_ok=1,fifo_bytes=0,int1_level=0,ok=1
READY,sensor=1,radio=1,clock_output=0,
clock_source=sensor_internal,clock_measurement=sensor_internal_fifo
STATUS,id=1003,state=1,gps=1,clock_hz=0.0000,ppm=0.00,
clock_ok=1,clock_source=sensor_internal,queue=0,
lost_samples=0,lost_packets=0
```
