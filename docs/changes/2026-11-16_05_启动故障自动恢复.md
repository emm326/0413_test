# 启动故障自动恢复

## 对应步骤

阶段 4～5 的单节点启动稳定性修复。目标是让 IIM42652 在一次瞬时启动自检失败或外部 32 kHz 误判后自动重新初始化，不依赖手动执行 `SENSOR_RETRY`，并且只在全部恢复尝试失败后进入 `Fault`。

## Git 基线

- 本轮基线：`96cdbe3`（docs: 更新项目交接与传感器当前状态）。
- 分支：`codex/sensor-recovery-20261114`。
- 接线、节点号、传感器、GNSS/PPS、频段和协议配置不变。

## 问题

上一轮交接记录中设备曾显示 `state=5`。固件状态定义中 `state=5` 表示 `Fault`。调查确认：

1. 传感器在手动 `SENSOR_RETRY` 后可以立即通过 WHO_AM_I、FIFO 和有效样本自检。
2. 原启动流程只执行一次 `initializeSensor()`。一次启动自检失败会把 `sensorReady_` 置为 0，节点随后锁存在 Fault。
3. GPIO36 的 32 kHz 信号可能在启动短窗口中被误判为合格，随后运行时看门狗发现频率不合格并再次进入 Fault。
4. 原逻辑没有把这种链路问题记录到 STATUS；外部时钟检测失败后也不会在空闲状态自动切换到传感器内部时钟。

## 做了什么

1. 新增启动恢复流程。
   - 每次启动最多执行 3 次完整初始化。
   - 每次失败后等待 300 ms 再进行下一次。
   - 任意一次成功即进入 `Waiting`。
   - 只有全部尝试失败才保持 `Fault`。
2. 加强外部时钟启动判定。
   - 启动验证窗口由 50 ms 延长到 500 ms。
   - 32.000 kHz 的有效边沿范围仍按 12,000～20,000 个/500 ms 校验。
   - 失败后只探测一次，避免每次传感器重试都重复等待无效外部时钟。
3. 新增运行时时钟看门狗回退。
   - 空闲且队列为空时，外部时钟连续失败不再直接锁死。
   - 关闭外部时钟输出，重新用 IIM42652 内部时钟初始化传感器。
   - 采样进行中或队列非空时仍进入 Fault，避免在采集过程中无提示切换时基。
4. 增加启动诊断字段。
   - `startup_attempts`：本次启动使用到第几次完整初始化。
   - `startup_failure`：`vendor_init`、`startup_checks` 或 `none`。
   - `fault_reason`：`sensor_startup`、`clock_watchdog`、`sensor_identity`、`sensor_fifo` 或 `none`。
5. 修正内部时钟诊断。
   - `SENSOR_SAMPLE_TEST` 不再要求 GPIO36 外部时钟可用。
   - `DIAG` 和 `SENSOR_LINK_TEST` 在内部时钟模式下也可执行。
6. 固件版本更新为 `3.0.1`。

### 连续冷启动

连续执行 3 次冷启动，3/3 均自动完成传感器自检：

```text
READY,sensor=1,radio=1,clock_output=0,
clock_source=sensor_internal,clock_measurement=sensor_internal_fifo
SENSOR_STARTUP_END,trigger=boot,ok=1,attempt=1
STATUS,state=1,clock_ok=1,startup_attempts=1,
startup_failure=none,fault_reason=none
```

3 次均未出现 `SENSOR_FAULT` 或 `state=5`。

2026-11-16 18:08 又执行第 4 次冷启动，结果仍为：

```text
SENSOR_STARTUP_END,trigger=boot,ok=1,attempt=1
READY,sensor=1,radio=1,clock_output=0,
clock_source=sensor_internal,clock_measurement=sensor_internal_fifo
STATUS,state=1,startup_attempts=1,startup_failure=none,fault_reason=none
```

冷启动后 `DIAG` 返回 `SENSOR_DIAG,who=0x6F,accel=0x49,power=0x00,fifo_cfg=0x80`，关键寄存器读回正常。该次日志为 `tmp/logs/com8_boot_20261116_180839.log`。


这说明传感器和射频初始化正常。当前 `gps=0` 是 GNSS/PPS 健康门槛，不是传感器启动故障。正式 START 仍需在 GNSS/PPS 恢复健康后执行。

## 当前结论

- 启动瞬时失败不再永久锁存为 `Fault`。
- 无效外部 32 kHz 在空闲状态会自动回退到传感器内部时钟。
- 连续 3 次冷启动和 50 Hz 60 秒采样均通过。
- 最终设备保留 `eora_s3_400_iim42652_tx`。
- LoRa 实际收包、ACK 和正式空口 60 秒验收仍需网关在线后完成。
