## 1. 核心结果

在不运行NodeApp、LoRa、GNSS及PCNT测频逻辑，并关闭PSRAM初始化的最小程序中，仍能复现以下两点：

1. 硬件SPI和独立软件SPI读取WHO_AM_I全部为0x00，尚未恢复IIM-42652预期的0x6F。
2. GPIO38输入跟随GPIO36输出电平/频率。在GPIO36固定低/高时，GPIO38分别保持低/高；1kHz、8kHz下200ms分别产生200、1600个上升沿。32kHz附近约6390个边沿，明显不属于50/100Hz采样中断。

这把问题进一步缩小到传感器接口、电气路径、供电或模块状态；不能归因于上位机、无线拥塞或原业务中断计数逻辑，也不能据此指认某根线接错或判定模块损坏。尚未测量传感器端供电电压和外部波形。

## 2. 保持配置与操作边界

- 同一USB身份90:DA:72:76:1F:30，COM8/460800，EoRa-S3-400TB + IIM-42652，节点1003。
- 固定接线：SCK47、MOSI48、MISO39、CS40、INT1输入38、CLKIN输出36；MISO和INT始终为输入。
- 初始保护版状态：WHO0、state5、queue0、gps1、clock_ok1、31999.3828Hz/-19.31ppm；未有待补传队列。
- 临时程序只读身份和少量配置，并尝试选择寄存器bank0；未执行传感器软复位、未启用采样、未发START、未改网关配置。
- 1kHz/8kHz仅用于链路诊断，正式32000Hz配置保持不变；测试结束恢复原保护版，未将临时频率用于实际采集。

## 3. 实机验证

### 3.1 两套诊断构建

- v1最小程序保留原PSRAM初始化，LoRa电源控制GPIO21置低；WHO仍全部为0，关闭时钟也不能恢复。
- v1最初1-bit分辨率无法产生1kHz/8kHz，驱动明确报错；两段结果无效，不纳入低频结论。原始失败日志保留。
- v2改用10-bit LEDC进行诊断，1000/8000/32000三个设置均返回ESP_OK，PSRAM实际打印0；GPIO21恢复与正式程序相同的高电平，但不初始化LoRa。
- 两个最小配置最终编译通过；均完成COM8烧录和Flash摘要校验。v1的首次编译遇到Arduino宏名冲突，改名后通过；未将失败尝试计为通过。

### 3.2 v2独立GPIO观测

每段200ms，输入模式依次为无上下拉/下拉/上拉。中断计数与直接读取GPIO寄存器的轮询计数分别保存。

| GPIO36输出 | GPIO38上升沿IRQ（无/下/上拉） | GPIO36轮询上升沿 | GPIO38电平行为 |
|---|---|---|---|
| 固定低 | 0 / 0 / 0 | 0 / 0 / 0 | 全部保持低 |
| 固定高 | 0 / 0 / 0 | 0 / 0 / 0 | 全部保持高 |
| 1kHz | 200 / 200 / 200 | 200 / 200 / 200 | 轮询电平一致率100% |
| 8kHz | 1600 / 1600 / 1600 | 1600 / 1600 / 1600 | 轮询电平一致率约99.97% |
| 32kHz诊断设置 | 6391 / 6390 / 6390 | 6390 / 6390 / 6390 | 轮询电平一致率约99.96%以上 |
| 再次固定低 | 0 / 0 / 0 | 0 / 0 / 0 | 全部保持低 |

v2的32kHz诊断采用不同分辨率，频率量化及计数窗口可能偏离正式时钟；本表只作跟随关系诊断，不作为±100ppm时钟验收。32kHz下IRQ与轮询偶有1–2边沿差，不能把两种计数当严格同时测量。

输出路由寄存器在切换LEDC时GPIO36由0x100变为0x49，而GPIO38始终0x100。程序只将GPIO38设为输入，未将该脚连接到LEDC输出。

### 3.3 SPI对照

- 6个时钟阶段 × 2种SPI模式（0、3）× 2种速率（100kHz、1MHz）× 8次 = 192次硬件WHO读取，全部0x00。
- 同样6阶段各8次独立软件SPI读取，共48次，全部0x00；软件SPI不依赖SPIClass、DMA或SPI输入矩阵。
- MISO无上下拉/下拉/上拉下的额外读取也全部0；bank、设备配置、供电模式、接口及中断配置均读0。全零不能解释为有效配置读回。
