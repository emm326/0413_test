- 日期：2026-11-13，Asia/Hong_Kong。
- 对应步骤：3/4/5，1003单节点时钟与传感器启动时序排查。
- 状态：进行中。主控时钟生成/路由/PCNT对照已完成；无时钟冷启动诊断已烧录并就绪，等待用户真实断电再上电后复查。
- 用户条件：接线确认无误，本轮全程保持原接线、供电入口、节点1003和COM8，不要求重接线。
- Git基线：75e0f1c995fb638a1175d1dd911e65fe798eb0d5，codex/e870-8-node；已保存快照与保护版，按既有约定暂不提交。

## 1. 当前能回答什么

本轮未发现32kHz时钟生成、GPIO输出矩阵或PCNT计数的明显软件错误：原项目SampleClock.cpp原样编入诊断，GPIO36每1秒读到32000个上升沿，约50%高电平；PCNT也约32001边沿。停用PCNT后GPIO38仍跟随GPIO36，因此不是把PCNT计数误当DRDY的结果。

GPIO36真正关闭输出缓冲、无上下拉时，GPIO36/38均无边沿；但硬件SPI和软件SPI身份仍全部0x00。换XTAL/APB时钟源、32/40kHz或暂停PCNT都未恢复0x6F。

这些结果不足以排除模块端输出电压、上升沿/振铃或传感器上电启动时序。尤其之前真实断电启动时跑的是“先启用时钟、再识别传感器”的保护版；本轮高阻对照期间没有给传感器重新断电，不能据此排除先前状态锁存。因此追加“上电始终高阻、先只读身份”的冷启动对照，已准备好实机，等待用户一次断电再上电。

## 2. 代码核对

- NodeApp::begin当前先clock_.begin(GPIO36)，随后sensor_.begin()；这是本轮继续核查的启动顺序疑点，尚未作为已确认根因。
- SampleClock使用XTAL时钟、LEDC低速timer0/channel0、1-bit分辨率、duty1；这是配置上的50%占空比。
- 历史LEDC路由被gpio_set_direction覆盖的问题，现有代码已使用先PCNT、后LEDC、再仅启用输入HAL的顺序；本轮原样代码实测确有输出，未复现历史“输出消失”。
- 诊断直接包含项目clock/SampleClock.cpp，未复制或替换其实现；GPIO轮询不调用DRDY ISR，也不依赖PCNT计算频率。
- GPIO36输出时enable36=1、route36=73（LEDC_LS_SIG_OUT0_IDX）；GPIO38始终enable38=0、route38=256，没有被程序配置为LEDC输出。
- PCNT启用后输入寄存器0xA4，对应输入矩阵选择GPIO36；暂停PCNT时输出路由不变。

## 3. 十阶段实机对照

每段窗口由esp_timer测量为1000000us。下表GPIO36和GPIO38边沿均由直接读取GPIO输入寄存器轮询所得；PCNT另独立计数。

| 阶段 | GPIO36上升沿/秒 | GPIO38上升沿/秒 | GPIO36高电平时间估计 | PCNT增量 | WHO |
|---|---:|---:|---|---:|---|
| 首次高阻，未配置时钟 | 0 | 0 | 输入保持高，无输出 | 0 | 0x00 |
| XTAL，仅LEDC 32kHz | 32000 | 32000 | 约49.58% | 0 | 0x00 |
| XTAL后高阻 | 0 | 0 | 输入保持高，无输出 | 0 | 0x00 |
| APB，仅LEDC 32kHz | 32000 | 32000 | 约49.44% | 0 | 0x00 |
| APB后高阻 | 0 | 0 | 输入保持高，无输出 | 0 | 0x00 |
| XTAL，仅LEDC 40kHz | 40000 | 40000 | 约49.4% | 0 | 0x00 |
| 项目原SampleClock+PCNT | 32000 | 32000 | 约49.98% | 32001 | 0x00 |
| 暂停PCNT，时钟仍开 | 31998 | 31998 | 约49.97% | 0 | 0x00 |
| 恢复PCNT，时钟仍开 | 31999 | 31998 | 约49.97% | 32001 | 0x00 |
| 最终高阻 | 0 | 0 | 输入保持高，无输出 | 0 | 0x00 |

- 原SampleClock窗口PCNT比轮询多约1–2边沿，包含窗口边界/读计数调用开销，不能当作传感器丢样；暂停PCNT增量0，但GPIO36/38仍约32000边沿。
- GPIO轮询存在中断和时间量化误差，31998/31999不能解释为已证实频率漂移；高电平时间约49.4–50.0%也不替代外部示波器占空比测量。
- 高阻阶段enable36=0，输入读到恒高；表中的恒高是引脚输入读值，不是ESP32主动输出100%占空比。停止后ledc_get_freq仍可能保留32000，因此本轮依据输出使能和实际边沿判断关闭，不能只看API频率返回值。
- XTAL32k、APB32k、XTAL40k设置均返回ESP_OK；40k仅用于诊断，正式32000Hz配置未改变。
- 十阶段各32次硬件身份读取（模式0/3、100kHz/1MHz），共320次；各16次软件SPI读取，共160次，全部0x00。
- 两种身份读取均只读0x75；此专项诊断没有写传感器寄存器、没有软复位传感器、没有启动采样。

## 4. 测量边界

板端GPIO读取与esp_timer使用同一主控时间基准，本轮测量主要验证分频、连续输出和计数逻辑，不是外部绝对频率校准。未使用GNSS连续PPS或示波器验收±100ppm，也未测传感器端电压、电平幅度、上升/下降沿和振铃。

GPIO38随时钟变化已经由直接输入寄存器复现；这说明存在需要进一步解释的信号跟随，但不能仅凭此定位到接线、模块、板卡或某个元件损坏。本轮尊重用户接线确认，不把软件对照失败转换成接线错误结论。

## 7. 下一步与用户操作

请保持接线不动，在当前已烧好的CLOCK_COLD_READY诊断下，将主控和传感器所有供电断开约10秒，再上电并告知。与前次断电不同，这次上电后始终不输出时钟；软件只能重启ESP32，无法代替传感器真实断电。

下一轮先只读WHO与输出使能。若恢复0x6F，继续验证“先识别并配置INT2/CLKIN，再启动时钟”的顺序，不能直接假定早启时钟已是根因；若仍0，记录无时钟冷启动也失败，再决定模块端波形/电压或对照模块检查。完成该对照后恢复原保护版；通信与自检正常后才进入50Hz及ACK/STOP。
