# 无时钟冷启动复查

- 日期：2026-11-13，Asia/Hong_Kong。
- 对应步骤：3/4/5，1003单节点时钟/传感器故障排查。
- 状态：待实测。ESP32时钟软件对照及本次无时钟冷启动检查已完成，传感器通信仍未恢复，真实采集/ACK/STOP未验收。
- 用户条件：承接上一轮全断电再上电操作，用户明确回复“我已重新上电”；沿用用户确认正确的接线与既有供电。实际断电条件依据用户确认，未伪造电源波形测量。
- Git基线：75e0f1c995fb638a1175d1dd911e65fe798eb0d5，codex/e870-8-node；按此前暂不提交约定保留工作区。

## 1. 做了什么

1. 先确认COM8及USB身份90:DA:72:76:1F:30，未触发复位/烧录，读取当前CLOCK_COLD_READY的REPORT与周期身份记录。
2. 首次读取之前没有发送CLOCK_XTAL_ON/CLOCK_APB_ON或其他启动时钟指令，避免破坏用户刚完成的无时钟冷态。
3. 通过CLOCK_OFF确认输出保持高阻，并独立轮询GPIO36/38一秒，随后继续读取身份。
4. 证据完整后，将原保护镜像写回COM8，Flash摘要校验通过；记录完整正式BOOT、传感器故障保护与最后STATUS。
5. 本轮没有编译、修改正式代码或运行正式采集；恢复的是已备份的同一367776字节保护版。

## 2. 实测结果

| 项目 | 结果 |
|---|---|
| 冷启动后GPIO36输出使能 | enable36=0，输出关闭 |
| GPIO38输出使能 | enable38=0，仅输入 |
| GPIO36/38输出路由 | 均256，未绑定LEDC |
| LEDC配置 | ledc_reported_hz=0，应用未启动时钟 |
| 一秒内GPIO36上升沿 | 0 |
| 一秒内GPIO38上升沿 | 0 |
| 硬件SPI身份读取 | 256次，模式0/3、100kHz/1MHz，全部0x00 |
| 独立软件SPI身份读取 | 128次，全部0x00 |
| 预期身份 | IIM-42652为0x6F，当前未得到有效身份 |

高阻时GPIO36/38输入读值均恒高，CLOCK_MEASURE中的duty1.0000是输入读值高电平比例，不是ESP32主动输出100%占空比。输出使能和一秒零边沿共同验证本次没有应用产生的周期时钟。

## 3. 对“是不是ESP32时钟”的结论

在用户重新上电、诊断应用始终不输出时钟的条件下，首次身份读取仍0；故本次识别失败不依赖应用先输出32kHz时钟。结合前轮XTAL/APB、原SampleClock和PCNT暂停对照，未找到能通过修改ESP32分频、时钟源或计数逻辑修复此故障的证据。

这不是对ESP32所有电气行为的全面合格证明：本轮未测上电瞬间模拟波形、模块端电压/幅度/振铃，也未作外部绝对精度验收。不能直接判定模块损坏或接线错误。后续应转向模块端实际供电与SPI应答电平，或已知正常模块对照，而不是继续重复同一时钟软件调整。
