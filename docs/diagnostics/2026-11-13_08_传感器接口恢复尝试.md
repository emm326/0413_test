- 日期：2026-11-13，Asia/Hong_Kong；对应步骤3/4/5，1003单节点识别恢复。
- 状态：待实测；本轮接口诊断与保护版恢复已完成，但未恢复有效身份，50Hz采样/ACK/STOP仍未验收。

## 1. 做了什么

先保存并只读校验原保护版；在GPIO36始终高阻、无采集/无线/GNSS的最小固件中，探测慢速四线SPI、三线SDIO以及同一组引脚的I2C。随后补一版显式GPIO输入使能与INPUT_PULLUP/INPUT_PULLDOWN对照，排除单纯输入未启用的读值误判。两版均完整运行，结束恢复原保护版。

SCK47/MOSI48/MISO39/CS40/INT38/CLK36保持。三线诊断在CS有效的读取阶段释放MOSI作为SDIO；I2C诊断将CS保持高，复用GPIO47为SCL、48为SDA，探测0x68/0x69。它们仅为寻找恢复通道，正式采集协议仍为原四线SPI。

## 2. 两版实机结果

| 检查 | 实测 |
|---|---|
| 硬件四线SPI | 每版模式0/1/2/3 × 10kHz/100kHz/1MHz × 16次，共192次，全部0x00 |
| 寄存器页选择恢复 | 尝试模式0/10kHz写REG_BANK_SEL=0；随后8次均未命中0x6F，不能宣称bank写入已确认 |
| 软件四线SPI | 每版四种模式各8次，共32次，全部0x00 |
| 软件三线SPI/SDIO | 每版四种模式各8次，共32次，全部0x00 |
| I2C 0x68/0x69 | 10kHz、100kHz下均error5超时，没有ACK或身份数据 |
| I2C输入配置复核 | v2显式gpio_ll_input_enable后mux47/mux48均0x1B00，SCL/SDA仍读0；配置中输入与上拉均开启 |
| GPIO47/SCK纯输入弱上拉 | 高读值0/100，输出使能0 |
| GPIO48/MOSI纯输入弱上拉 | 高读值0/100，输出使能0 |
| GPIO39/MISO纯输入弱上拉 | 高读值0/100，输出使能0 |
| 三脚纯输入弱下拉 | 高读值同样0/100，输出使能0 |
| 诊断结束 | recovered0，clock_output_enabled0，sampling_started0 |

这里“0”是主控数字输入读值，不是已用仪表测得0V，也不能凭此定位低电平来源。仍需区分模块供电、稳压/电平电路、模块/主控引脚电气状态等因素。

手动开漏总线恢复尝试发送9个SCL脉冲和STOP。v1/v2的该步骤早期电平日志来自输出模式，不作为有效电压判断；有效结论来自Wire初始化后显式输入使能，以及最后INPUT_PULLUP纯输入测试。没有将“发送恢复脉冲”写成总线已恢复。

I2C只是寻找备用控制通道，当前超时不能单独证明模块I2C模式、外部上拉或电平条件已满足，更不能据此直接判芯片损坏。

## 3. 软件复位为什么未计为成功

芯片手册定义DEVICE_CONFIG.SOFT_RESET_CONFIG，可通过有效串行接口写入后复位。诊断程序预置了稳定读到0x6F后恢复四线模式或发送复位并回读的路径，但本次一直没有有效身份，未进入这些路径，日志无RECOVERY_RESET/RECOVERY_I2C_RESET。

这是本轮的验证门槛，并非芯片技术上要求“必须先读身份才能接收复位”。可以单向尝试发送已知复位命令，但在没有有效回读时不能确认命令是否被接收或复位是否生效；不能把重刷ESP32、改sensorReady标志或仅写出一条命令当成传感器恢复。本轮只作一次已知bank选择尝试，没有盲写接口配置、修改厂家校准区或绕过故障保护。

已确认的边界是：本轮没有找到可验证的软件恢复入口。此前完整断电、无时钟冷启动也未恢复。继续恢复需要新的模块端电压/信号测量或正常模块对照，当前证据仍不足以判定某个器件损坏。

## 6. 下一步：恢复识别所需的新证据

保持用户确认的接线，先在模块端用直流电压挡测VCC对GND电压，再依据模块电路确认VDD/VDDIO与SPI电平。若模块供电/电平不满足其规格，应修复对应供电/电平问题；不能在没有模块规格时直接把VCC提高到5V。

供电确认后，测CS/SCK是否到达模块、MISO是否有有效输出；有仪表时同时观察CLKIN/INT1。必要时用已知正常模块对照。恢复稳定0x6F并通过DRDY/FIFO自检后，再继续原50Hz/25组打包/ACK/STOP验收。
