# 原厂驱动六线导入测试

## 对应步骤

2026-11-15 原厂驱动六线导入测试。目标是证明 IIM42652 可以通过六线 SPI 完成启动并持续产生加速度样本。

## 做了什么

1. 停止在旧 `IimBase` 链路上继续修改。
2. 学习原厂 `IIM42652-NUCLEO-G070` 示例和 Ixm42xxx 1.1.1 驱动。
3. 按原厂 `Src/main.c` 的 SPI 时序移植寄存器事务：CS 低、发送 `地址|0x80`、连续读取、CS 高；写入使用 `地址&0x7F`。
4. 新建独立 PlatformIO 环境 `eora_s3_400_iim42652_bringup`，不编译旧采集固件。
5. 增加 SPI 候选链路预检。每个组合连续读取 3 次 WHO_AM_I，稳定为 `0x6F` 才继续。
6. 预检通过后调用原厂 `inv_ixm42xxx_init()`，不使用手写的替代初始化。
7. 关闭 FIFO，设置 ±4g、50Hz，只启动加速度低噪声模式，等待 20ms，再轮询寄存器 5 秒。
8. 统计样本数、样本率、XYZ 均值、合向量、最小值和最大值，并在结束时关闭加速度。
9. 增加 5 秒启动倒计时，便于烧录后接入串口监视器并完整捕获启动日志。

## 接线与操作

测试阶段不接 INT1、CLKIN、GNSS 或 LoRa。固定六线如下：

| IIM42652 模块 | EoRa-S3-400TB |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SCK | GPIO47 |
| MOSI | GPIO48 |
| MISO | GPIO39 |
| CSB | GPIO40 |

烧录和读取命令：

```powershell
pio run -e eora_s3_400_iim42652_bringup -t upload --upload-port COM8
pio device monitor -p COM8 -b 460800
```

## 实机结果

- 端口：COM8，USB-Serial/JTAG。
- 预检：`hspi_mode0_100k` 连续 3 次读到 `0x6F`。
- 原厂初始化：`rc=0`。
- 关闭 FIFO：`rc=0`。
- WHO_AM_I：`0x6F`。
- 物理配置：`INTF_CONFIG0=0x50`，`PWR_MGMT0=0x03`，`ACCEL_CONFIG0=0x49`，`INT_STATUS=0x08`，DRDY=1。
- 采样：5 秒 247 个样本，49.4Hz，SPI 错误 0。
- XYZ 均值：`-694.8 / -5141.4 / 6492.8`。
- 合向量：1.0145g。
- 安全关闭：`PWR_MGMT0=0x00`，`accel_off=1`。
- 最终结果：`BRINGUP_RESULT,result=PASS,samples=247,rate_hz=49.400,mean_g=1.0145`。

## 关键修正

第一轮实机测试已经能稳定采样，但合向量显示 4.058g。原因是代码把 ±4g 的灵敏度写成了 2048 LSB/g。

DS-000440 的加速度灵敏度表写明：

| 量程 | 灵敏度 |
|---|---|
| ±16g | 2048 LSB/g |
| ±8g | 4096 LSB/g |
| ±4g | 8192 LSB/g |
| ±2g | 16384 LSB/g |

将代码修正为 8192 LSB/g 后重测，合向量为 1.0145g，与静止状态一致。启动、采样率和数据合理性均通过。
